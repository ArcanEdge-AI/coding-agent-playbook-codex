# September 2026 instruction evaluation

This is a historical evaluation record, not a description of the repository's current global instructions or the user's current installed Codex configuration.

The global instruction source received nine previously prepared substitutions: conditional delegation (two), reuse of existing authorization, capability-specific blockers, host instruction hierarchy, reuse of supplied choices, deliverable/fact fidelity, observable validation, and bounded completion.

The candidate was prepared before the DeepSWE coding comparison. At the time, it retained the then-current Luna/max child route, depth limits and other engineering rules. Those retained choices were unresolved hypotheses, not proven optimal policies. Installation was explicitly authorized while the revised coding arm was being evaluated; installation is not a claim of improved reliability.

The companion `coding-agent-playbook-benchmarks` repository records the research under `research/`, including the earlier skill isolation correction, controlled response screens, real TypeScript work, known-answer calibration and the three-arm DeepSWE protocol. At the close of this evaluation, the maintained source matched the normalized body of the frozen revised snapshot and the installed global retained its managed wrapper. Later instruction revisions and installations must be verified independently.

## Companion playbook scope

The generic principles evaluated here were compatible with the companion Claude Code playbook at the time: retain user authority, inspect the problem, preserve unrelated work, verify results and keep consequential decisions with the root. The nine substitutions were evaluated through Codex's native AGENTS.md discovery, native helper tools and reported session usage. That harness-specific evidence does not establish the same behavioral effects in Claude Code. This evaluation changed only the authorized Codex source and installed Codex globals; it did not copy model routes or orchestration policy into the independently maintained companion implementation.

The strongest claims remain bounded to the tested cases. In particular, response-only screens cannot establish live workflow success, and three known coding tasks with single attempts cannot establish general causal improvement. Keep new experiments reproducible, preserve failed attempts and known oracle limitations, and use an unseen confirmation set before generalizing.

## Completed DeepSWE comparison

All eighteen revised attempts completed grading. Raw whole-task passes were 2/18 without custom globals, 6/18 with previous globals and 4/18 with revised globals. Excluding the confirmed baseline Go grader-overlay fault from the common comparison gives 2/17, 5/17 and 3/17. The direct previous-versus-revised comparison retains all eighteen valid pairs. Known oracle ambiguities and committed-only submission limits remain part of the interpretation; no grades were changed.

Compared with previous globals, the revised arm used ten instead of nineteen helpers, 25.6% less uncached input and 14.4% fewer output tokens, while summed native author time increased 1.9%. It had eight author timeouts versus six, with six empty committed patches in both arms. These are mixed pilot results, not evidence of a generally superior global policy or an optimal helper route. The authorized revision remained installed when the evaluation closed; full results and limitations are recorded in the benchmark repository.
